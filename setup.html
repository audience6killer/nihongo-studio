Sync and hosting setup

Everything here is optional. The app works completely offline with no account.

What sync does, and what it does not.

Every answer is written to this browser first. Supabase holds a mirror of that state so your phone and your computer agree. It is never the source of truth: if the network is down, or the project pauses, you keep studying and nothing is lost. What leaves the device is one sanitised snapshot per account — no analytics, no page views, and no session tokens in the uploaded copy.

1. Create a Supabase project

  1. Sign in at supabase.com/dashboard and create a new project.
  2. Open Project Settings → Data API and copy the Project URL and the anon / publishable key. Both are public by design.
Give every language app its own project The sync table has one row per account. If two apps share a project and you sign in with the same email, they overwrite each other. One project per app is the simplest isolation there is.

3. Enable email sign-in

  1. Authentication → Sign In / Providers: make sure Email is enabled.
  2. Authentication → Users → Add user (or sign up from the app) to create your account.
  3. Then, if you want nobody else to be able to register, Authentication → Sign In / Providers → Email and switch off Allow new users to sign up.
Turn off sign-ups, not the provider Disabling the Email provider stops you signing in as well. “Email logins are disabled” is a provider setting, not a wrong password.

4. Point the build at the project

The deployed site is configured with two environment variables, read at build time:

VariableValue
SUPABASE_URLhttps://<project>.supabase.co
SUPABASE_ANON_KEYthe anon / publishable key

On Netlify: Site configuration → Environment variables, then Deploys → Trigger deploy → Clear cache and deploy site. Environment variables are baked in at build time, so saving them does nothing until a new deploy runs. The build log must say supabase: configured at build time.

Running locally instead? npm run build with the same variables set, or paste the URL and key directly into Settings → Cloud sync in the app.

Never ship the secret key The build refuses a key that looks like service_role. The anon key is protected by Row Level Security; the secret key bypasses it and must never reach a browser.

5. Sign in and verify

  1. Open the app, go to Settings → Cloud sync, and sign in.
  2. Study a little, then press Sync now. Open the same page on the other device, sign in, and the progress merges.
  3. Check Settings → Data → Export backup opens a JSON file with no accessToken in it — that is by design.

6. Hosting

The repository ships a Netlify contract: connect the repo, build npm run build, publish deploy, Node 20. The service worker is content-hashed on every build, so a new deploy always installs a fresh cache. After deploying, set the Supabase Site URL to the new address so confirmation emails point somewhere real.

iPhone “Add to Home Screen” installs the offline app. A private Netlify site gates the files, not your progress row, and a home-screen app may not share the Netlify session — a public site protected by Supabase auth is usually the smoother arrangement.
